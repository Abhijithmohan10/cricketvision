\chapter{Development Methodology}

The \textbf{CricketVision: AI-Powered Cricket Performance Analytics and Biomechanics Platform} was developed using an iterative and incremental approach. The project was divided into smaller functional modules and developed step by step. Each module was implemented and tested before integrating it with the other parts of the application. This approach made it easier to identify errors, make changes, and gradually build the complete system.

The main development activities included requirement identification, system planning, implementation of the major modules, testing, and final integration. Git was used for version control and to maintain the development history of the project.

\section{Development Approach}
The project follows an iterative development approach with basic Scrum practices. Instead of developing the complete application at once, the required features were divided into smaller tasks and implemented progressively. The main modules were developed according to their importance and dependency on other modules.

The initial development focused on user registration and login supporting persona presets (\texttt{Rahul Dravid}, \texttt{Virat Kohli}, \texttt{Jasprit Bumrah}, \texttt{Alex Morgan}), followed by player profile management and MongoDB database seeding (104 player profiles). SVG wagon wheel shot dispersion heatmaps and Recharts skill radar charts were then implemented.

After the player performance data could be stored in a structured form, the Stochastic Match Simulator engine and win-probability calculation logic were developed. Video pose estimation biomechanics analysis and AI Coach strategy recommendations were implemented using the stored player data and canvas rendering engines.

This approach allowed each feature to be tested during development. Problems identified during testing were corrected before proceeding with further integration. Regular Git commits were also used to record important development stages and changes.

\section{Requirement and Planning}
The first stage of development involved identifying the requirements of the application. The main requirement was to provide a single platform where coaches, players, and analysts could manage squad rosters, analyze phase-wise statistics, simulate match outcomes, audit video bowling kinematics, and receive AI-assisted strategy advice.

The functional requirements identified for the system included:
\begin{itemize}
    \item User registration and secure login supporting persona presets.
    \item Roster creation, profile editing, and automated MongoDB player seeding (104 documents).
    \item Phase-wise performance statistical breakdown (Powerplay, Middle, Death overs).
    \item 360-degree SVG wagon wheel shot dispersion heatmaps and pitch length plots.
    \item Stochastic ball-by-ball match simulation and dynamic win-probability curve generation.
    \item Markerless video pose keypoint tracking and ICC 15-degree bowling action compliance auditing.
    \item Natural language AI Coach strategy advice and Team Builder XI balance optimization.
\end{itemize}

The system was planned as a web application with separate frontend and backend components. React 18 with Vite was used for the frontend, while Node.js and Express.js were used for the backend. MongoDB with Mongoose ODM was selected for storing user and player information.

The database was planned to store structured player documents so that the same data could be used by different modules. This reduced repeated data entry and allowed player information to be reused for wagon wheel rendering, match simulation, video kinematics auditing, and strategy advice generation.

\section{Implementation}
The implementation was carried out module by module. The authentication module was developed first to provide registration, login, and persona preset switching functionality. Passwords were securely processed using password hashing.

The roster management module was then implemented to allow users to enter, save, edit, and manage player performance records. An automated database seeding controller was built in \texttt{server.js} to verify player collection size on cold boot and auto-seed 104 verified international and IPL player documents.

The visual analytics module was constructed using React SVG graphics and Recharts. The component \texttt{PitchAndWagonWheel.jsx} converts polar shot coordinates into Cartesian SVG canvas points across 8 stadium sectors.

The Stochastic Match Simulator module uses stored player data and live match inputs (target score, current over, wickets lost, pitch friction, weather impact) to calculate dynamic win-probability curves $P_{\text{win}}$ using a logistic regression formula.

The Video Biomechanics Analyzer module renders video playback on an HTML5 canvas overlaying skeletal keypoint lines, computing elbow flex angles $\theta_{\text{elbow}}$, and auditing bowling action legality against ICC limits.

The AI Coach module connects to the Google Gemini API to generate contextual natural language strategy advice based on squad stats and fatigue indicators.

The frontend and backend components communicate through REST APIs. The backend handles authentication, database operations, match simulation logic, and pose telemetry calculations, while the frontend provides the interactive user interface for accessing these functions.

\section{Testing and Validation}
Testing was performed throughout the development process to verify that the implemented features worked correctly. Each major module was tested individually before being integrated with the complete application.

The authentication module was tested using valid credentials, incorrect passwords, and persona preset switches. Roster creation and editing were tested by entering different types of player statistics and verifying database persistence.

Automated seeding was tested by dropping the local MongoDB player collection and verifying that cold server boots correctly inserted all 104 player profiles in sub-2.0 seconds.

The Stochastic Match Simulator was tested using historical match scenarios to verify that the calculated win-probability curve responded dynamically to wicket losses and pitch condition changes.

The Video Pose Analyzer module was tested using bowling video feeds to verify that joint flexion angles were computed accurately and that illegal actions ($> 15^{\circ}$) triggered prominent red alerts.

After individual module testing, the complete application workflow was tested from user login through squad management, wagon wheel rendering, match simulation, video pose analysis, and AI strategy advice generation. The final testing ensured that all modules communicated correctly through REST APIs and that the developed system performed its intended functions.

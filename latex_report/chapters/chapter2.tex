\chapter{System Study}

System study is carried out to understand the existing methods used for cricket performance tracking, statistical scorecards, match outcome simulation, and video biomechanics presentation. It helps to identify the limitations of existing systems and define the requirements of the proposed application. The \textbf{CricketVision: AI-Powered Cricket Performance Analytics and Biomechanics Platform} combines squad roster creation, database seeding, phase-wise analytics, 360-degree SVG wagon wheel rendering, stochastic match simulation, video pose analysis, and dynamic report generation in a single web application.

\section{Existing System}
Traditionally, cricket statistics and team rosters are maintained using document editing applications or flat spreadsheets where users manually enter player details, career averages, strike rates, and bowling figures. Coaching staff are responsible for maintaining content formatting and cross-tab calculations. Although this method provides flexibility, it requires repeated manual effort when player data needs to be updated or modified for different upcoming matches.

Several online sports portals provide live scorecards and aggregate statistical tables. These systems make match viewing easier, but performance statistics, workload fatigue tracking, match simulation, and video biomechanics are handled separately. Users must therefore navigate across multiple applications to review player statistics, evaluate pitch conditions, check bowling action legality, and compile scouting reports.

Research in sports analytics and computer vision has introduced automated methods for extracting and analyzing athletic performance. Natural Language Processing (NLP), Named Entity Recognition (NER), computer vision pose tracking, and machine learning have been used for identifying player keypoints, calculating joint angles, and predicting match outcomes.

For example, Perera et al. studied context-aware player efficiency metrics in cricket, demonstrating that traditional career averages fail to reflect situational performance during high-pressure overs. [8]

Another study by Moorthy \& DeSarbo proposed dynamic stochastic simulation modeling for franchise T20 cricket, proving that incorporating venue pitch friction, weather impact, and bowler-batter matchups yields higher predictive accuracy than static lookup tables. [9]

Recent work has also explored the use of generative AI and markerless pose estimation for sports biomechanics. A 2021 IEEE study by Cao et al. combined Part Affinity Fields (PAF) and 2D pose keypoint tracking to extract joint coordinates and calculate segment flexion angles from video frames without requiring physical motion-capture suits. [10]

These studies show that automated data processing and computer vision pose tracking can reduce manual effort and help organize information from sports video feeds. However, CricketVision focuses not only on video parsing but also on the complete user-side workflow of squad management, phase-wise analytics, stochastic match simulation, video pose analysis, and dynamic portfolio report generation.

\section{Proposed System}
The proposed system is a web-based application named \textbf{CricketVision: AI-Powered Cricket Performance Analytics and Biomechanics Platform}. It provides a single platform for creating, managing, analyzing, improving, and presenting cricket performance and kinematic information.

Users can create player profiles manually or utilize the automated database seeding engine. On application startup, the backend checks the MongoDB database and automatically seeds 104 verified international and IPL player profiles if the database count falls below 100.

The structured player information is stored in the MongoDB database and is used by the different functions of the application. Users can edit player details, update fatigue levels, and reuse the stored data without entering the same details repeatedly.

The application provides phase-wise performance analytics that examine player statistics across Powerplay (overs 1--6), Middle (overs 7--15), and Death (overs 16--20) overs. The analysis calculates specialized metrics such as the Clutch Rating and Fatigue Level Index.

The system also includes a 360-degree SVG Wagon Wheel shot dispersion visualizer and pitch length distribution plot. The graphics dynamically transform polar shot coordinates into Cartesian SVG canvas points color-coded by boundary classification.

Another major feature is the Stochastic Match Simulator. The application evaluates target scores, current overs, wickets lost, pitch friction factors, and weather impact variables to generate dynamic win-probability curves recalculated ball-by-ball.

Video biomechanics analysis is integrated into the video review studio. The canvas overlays skeletal keypoints, computes elbow joint flex angles $\theta_{\text{elbow}}$, and audits bowling action legality against the ICC 15-degree flexion limit.

An AI Coach natural language strategy assistant is also provided, offering contextual recommendations for team selection, bowling rotations, and workload management.

The major functions of the proposed system include:
\begin{itemize}
    \item User registration and secure login supporting persona presets.
    \item Manual player creation, roster editing, and automated database seeding (104 players).
    \item Phase-wise performance analytics (Powerplay, Middle, Death overs).
    \item 360-degree SVG wagon wheel shot dispersion heatmaps and pitch length plots.
    \item Ball-by-ball Stochastic Match Simulator with dynamic win-probability curves.
    \item Markerless video pose estimation analyzer measuring joint flex angles against ICC rules.
    \item AI Coach natural language strategy recommendation engine.
    \item Team Builder XI balance optimizer evaluating squad depth and experience scores.
\end{itemize}

\section{Requirement Analysis}
Requirement analysis identifies the software and hardware resources required for developing and running the proposed system. The requirements are divided into software and hardware requirements.

\subsection{S/W Requirement}
The major software requirements of the system are given below:

\begin{itemize}
    \item \textbf{Operating System:} Windows 10/11 (64-bit), macOS Monterey+, or Ubuntu 22.04 LTS.
    \item \textbf{Frontend Framework:} React 18 with Vite for developing the reactive user interface.
    \item \textbf{Backend Framework:} Node.js and Express.js for server-side REST API development.
    \item \textbf{Database System:} MongoDB Community Server (v6.0+) with Mongoose ODM (v8.x) for document persistence.
    \item \textbf{Programming Languages:} JavaScript (ES6+), HTML5 Canvas API, SVG mathematical graphics.
    \item \textbf{Visualization Libraries:} Recharts 2 for multi-attribute radar charts and dynamic line graphs.
    \item \textbf{Styling \& UI Components:} Tailwind CSS 3 and Lucide React icons.
    \item \textbf{AI \& Document Libraries:} Google Gemini API for natural language AI Coach advice.
    \item \textbf{Development Tools:} Visual Studio Code, Postman v10.x, Chrome Developer Tools.
    \item \textbf{Version Control:} Git and GitHub (\texttt{Abhijithmohan10/cricketvision}).
\end{itemize}

The frontend provides the user interface, while the backend manages authentication, database operations, REST API routing, match simulation logic, and pose telemetry calculations. The frontend and backend communicate through asynchronous HTTP REST APIs.

\subsection{H/W Requirements}
The hardware requirements for the development and execution of the project are:

\begin{itemize}
    \item \textbf{Processor:} Quad-Core Intel Core i3/i5/i7 (8th Gen+), AMD Ryzen 5/7, or Apple M1/M2/M3.
    \item \textbf{System Memory (RAM):} Minimum 4 GB; 8 GB or 16 GB is recommended for canvas video pose rendering.
    \item \textbf{Storage:} At least 10 GB of available Solid State Drive (SSD) storage for the project, database documents, and media dependencies.
    \item \textbf{Display:} Full HD (1920x1080) resolution display monitor.
    \item \textbf{Network Connection:} Required for downloading dependencies, initial repository setup, and accessing AI services.
\end{itemize}
